# engine/ — the importable engine package

The package wraps the single-file core `dynamics.py` into four CLI-capable modules.
Everything imports the core directly (`sys.path` bootstrap), so the package carries
**zero dependencies** beyond the standard library.

## Files

| File | Role |
|---|---|
| `particles.py` | the three-layer facade: `ThreeLayerModel(fen)` exposes the threat field Θ(c), the Lagrangian energy E, the mobility sums, the t\* flow read-out and the group reductions of a position; `--demo` prints the full read-out of the initial position |
| `mate_solver.py` | the forced-mate solver: iterative deepening over the mate DFS with the full PV (the most resistant defender replies); `--fen "<FEN>" --max N` |
| `game_player.py` | the playing engine: negamax + quiescence + MVV-LVA, deterministic self-play; `--fen`, `--depth`, `--moves`, `--selfplay` |
| `analyzer.py` | the position analyzer: the best line, the node count, the energy/mobility breakdown, the threat heatmap in ASCII; `--fen "<FEN>" --depth N` |

## Examples

```bash
python3 engine/particles.py --demo
python3 engine/mate_solver.py --fen "kbK5/pp6/1P6/8/8/8/8/R7 w - - 0 1" --max 5
# -> mate in 3 plies, key a1a6, PV a1a6 b7a6 b6b7 (46 nodes)
python3 engine/game_player.py --selfplay --depth 4
python3 engine/analyzer.py --fen "r1bqkbnr/pppp1ppp/2n5/4p3/4P3/5N2/PPPP1PPP/RNBQKB1R w KQkq - 2 3" --depth 4
```

## Guarantees

- **Determinism**: the same FEN + depth always yields the same move, score and node
  count (total move order — theorem T10(iv)).
- **Legality**: every engine move is generated by the same perft-certified generator
  as the core (theorem T08).
- **Honesty**: `game_player.py --selfplay` reproduces bit-identical games on any
  platform; the CI runs it twice and compares.

## In-process usage

```python
import sys; sys.path.insert(0, ".")
from engine.mate_solver import solve
plies, pv, nodes = solve("7k/8/5N1K/8/8/8/8/6R1 w - - 0 1", max_depth=3)
assert plies == 1 and pv[-1].uci == "g1g8"
```
